# Tripper.AI

A merch store for pilgrimage-themed **magnets** and **posters**, built with Next.js 15 (App
Router) and TypeScript. Dark, cinematic theme (`#0a0a0a` background, `#f48b29` accent).

> **Working on the code?** `AGENTS.md` is the source of truth for architecture and conventions,
> `CHANGELOG.md` for version history, `ROADMAP.md` for what's planned. This README is the
> human-friendly overview.

---

## Tech stack

| Layer | Choice |
|-------|--------|
| Framework | Next.js 15 App Router, React, TypeScript (strict) |
| Styling | Tailwind CSS v4, shadcn/ui, `lucide-react` icons |
| Auth | [better-auth](https://better-auth.com) — email/password + Google OAuth |
| Database | PostgreSQL via Drizzle ORM (`postgres.js` driver) |
| Payments | Razorpay (currently test mode) |
| Cart | Zustand + localStorage (client-only) |
| Security | Arcjet (shield + rate limits, currently DRY_RUN) |

## Getting started

```bash
npm install
npm run dev      # dev server (Turbopack) on http://localhost:3000
```

Other commands:

```bash
npm run build    # production build
npm run start    # serve the production build
```

There is **no** lint or test script.

### Environment variables

Create `.env` with (validated in `src/env.ts`):

| Variable | Required | Purpose |
|----------|----------|---------|
| `DATABASE_URL` | ✅ | PostgreSQL connection string |
| `BETTER_AUTH_SECRET` | ✅ | Signs session cookies (min 32 chars) |
| `BETTER_AUTH_URL` | – | Auth base URL |
| `NEXT_PUBLIC_APP_URL` | ✅ | App URL for the auth client |
| `ARCJET_KEY` | ✅ | Arcjet security key |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | – | Google OAuth |
| `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` | – | Razorpay server keys |
| `NEXT_PUBLIC_RAZORPAY_KEY_ID` | – | Razorpay client key |
| `ADMIN_EMAILS` | – | Comma-separated emails allowed into `/admin` |

### Database

Schema lives in `src/lib/db/schema.ts`. Push it with Drizzle (no npm script):

```bash
npx drizzle-kit push
```

The auth tables (`user`, `session`, `account`, `verification`) are **generated by better-auth** —
regenerate with `npx @better-auth/cli generate` after changing auth config, then push. Don't
hand-edit them.

## How it works

### Auth flow

better-auth handles sign-in/up (email/password + Google). Sessions live in a signed, httpOnly
cookie backed by the `session` table.

1. **Cookie cache** — session data is cached in the signed cookie (`maxAge` 5 min), so most
   session checks skip the database entirely. Security gates (`/admin` and the admin API) opt out
   with `disableCookieCache: true` so a revoked user is blocked immediately.
2. **Server prefetch** — the root `layout.tsx` reads the session on the server and passes it to
   `AuthProvider`, which hydrates the client. The signed-in UI shows on first paint — no extra
   round trip, no signed-out→signed-in flash.
3. **Client** — components read state through `useSession()` (from `auth-provider.tsx`), which
   revalidates in the background.

### Shopping → checkout

1. **Cart** is client-only (Zustand + localStorage, key `tripper-cart`). The server never reads
   it. Each mutation is Zod-validated.
2. **BUY NOW** on a product adds it to the cart and redirects to checkout — but only if the
   customer is signed in; otherwise they're sent to sign-in first.
3. **Checkout** — the client POSTs `{ items, addressId }` to `/api/checkout`, which creates a DB
   order plus a Razorpay order and returns the `razorpayOrderId`.
4. **Payment** — the Razorpay checkout.js modal runs client-side; on success the client POSTs to
   `/api/verify-payment`, which verifies the signature server-side (HMAC SHA-256).
5. **Webhook** — Razorpay sends `payment.captured` to `/api/webhooks/razorpay`, which updates the
   order status.

> All monetary amounts are stored in **paise** (integers). `amountPaise = totalAmount * 100`.

### Admin

`/admin` is gated by the `ADMIN_EMAILS` env var (server-side check). Three tabs:

- **Orders** — view all orders, update delivery status (pending / shipped / delivered / cancelled).
- **Interest** — journal waitlist email signups.
- **Accounts** — registered users who haven't ordered.

## Status & caveats

- **Razorpay is in test mode** — rotate to live keys and update the webhook URL before real
  transactions.
- **Arcjet rate limits are DRY_RUN** — logged, not enforced. Switch to `LIVE` when ready.
- **Cart is localStorage only** — clearing browser storage loses the cart.
- **No CMS** — product data is hardcoded in components; adding products means code changes.
